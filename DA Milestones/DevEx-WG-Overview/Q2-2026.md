## 3. Strategic Assessment & Pain Points

This section draws from the **Intersect State of Developer Experience Survey 2026** — 55 responses collected in June 2026 — alongside observations from Q2 community events and working group sessions.

### 3.1 Current Status (High-Level Assessment)

| Area | Status | Priority |
| :--- | :--- | :--- |
| **Debugging & Dev Environment** | ⚠️ Open Gap | High |
| **Developer Onboarding** | ⚠️ Needs Improvement | High |
| **Documentation Quality** | ⚠️ Partial | High |
| **Funding & Opportunities** | ⚠️ Open Gap | High |
| **Tooling** | ⚠️ Partial | Medium |
| **Community & Intersect Visibility** | ⚠️ Partial | Medium |
| **Language Access** | ⚠️ Open Gap | Medium |
| **Session Accessibility** | ✅ Good | Low |
| **Website Infrastructure** | ✅ Stable | Low |

### 3.2 Key Survey Findings

55 developers responded. 47.3% are active builders. 49.1% have 6+ years of professional development experience. 54.5% rated their motivation to build on Cardano at 5/5.

**Top findings:**

- 61.5% cited Getting Started, Tooling, and Documentation as their top challenges.
- 45.5% rate documentation as neutral; 25.5% rate it as difficult.
- No offline dev environment exists. Debugging requires preview/preprod. Error messages are cryptic.
- No canonical front door to Cardano developer docs — split across CF, IOG, Intersect, and individual project repos.
- Catalyst is perceived as a popularity contest; merit and popularity are not separated.
- 34.5% of respondents are not Intersect members. 18.2% do not know what Intersect is.
- Community is rated the number one ecosystem strength, described as collaborative and generous.
- Aiken and yaci-devkit are the tooling bright spots, both praised without prompting.

### 3.3 Resolved in Q2 2026

| Pain Point | Resolution |
| :--- | :--- |
| **Session Discoverability** | Maintained from Q1 via DevEx site Floating Action Button and calendar integration. |
| **Node Setup Friction** | Addressed in live workshop at Minnesota Open Source Summit — Mithril and YACI Dev Kit demonstrated as practical alternatives to full node sync. |
| **MCP Tooling Gap** | Session 19 delivered a working Cardano MCP server demo, providing a reference integration point for AI agent tooling on Cardano. |

### 3.4 Consolidated Pain Points & Solutions

| Category | Pain Point | Proposed Solution |
| :--- | :--- | :--- |
| **Debugging** | No offline dev environment. Preview/preprod responses are cryptic. No line-level validator feedback. Mesh and Lucid ship no default logging. | Fund a production-ready offline environment (TX3/yaci-devkit). Publish a Common Errors Reference. Require SDK structured debug logging. |
| **Documentation** | No canonical front door. Docs fragmented across CF, IOG, Intersect, and project repos. No freshness policy. No conceptual middle layer between beginner intros and raw API references. | Single opinionated getting-started flow with one canonical front door. Assign doc maintainers per module. Add last-verified dates to every page. |
| **Onboarding** | eUTXO model is foreign to Ethereum and Solana developers. No browser-based sandbox. No scaffolded developer journey based on persona or use case. | Define 2–3 developer personas with tailored learning paths. Browser-based sandbox targeting zero to first testnet transaction in under 1 hour. Dedicated eUTXO vs. account-model guide. |
| **Tooling** | Many tools solving the same problems with no capability comparison. Nix is a barrier. Contributing to core repos is unclear. | Published tooling capability matrix. Dedicated Nix onboarding guide. Every major repo needs a beginner-accessible CONTRIBUTING.md with labelled good first issues. |
| **Funding & Opportunities** | Catalyst seen as a popularity contest. Few job opportunities outside the community. Opportunities exist but are hard to discover without insider connections. | Centralised job and grant board. Structured technical review lanes in Catalyst with credentialed reviewers. Plain-language overview of all current monetisation paths. |
| **Community & Intersect Visibility** | 34.5% not Intersect members. 18.2% do not know what Intersect is. Opportunity access is gatekept. 87.3% rely on social media as primary info source. | Developer-targeted Intersect outreach with a concrete value proposition. Opt-in mentorship matching. Curated technical newsletter. |
| **Language Access** | ~36% want materials in languages other than English. Language support rated important by 38.2% at 5/5 importance. | Translate 5–10 critical onboarding docs into French, Spanish, and Swahili as wave one. Support regional community channels in key languages. |

### 3.5 Plan for Improvement

- **Short term:** Publish eUTXO vs. account-model guide; complete session gaps (15–17, 19–20); launch curated list of good first issues.
- **Medium term:** Establish canonical docs front door; publish tooling capability matrix; launch job and grant board; formalise ADA Sisters programme with WIMS-Cardano.
- **Long term:** Commission wave one translations; drive Catalyst technical review reform; align DevEx metrics with OSC Open Source Strategy.
